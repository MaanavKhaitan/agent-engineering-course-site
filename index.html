Agent Engineering: From Fundamentals to Production

A hands-on, sequential course that takes you from “I’ve used an LLM API” to “I can design, build, evaluate, and deploy a production agent system.” Written for an experienced software engineer who hasn’t worked much with AI agents yet.

The one-sentence thesis of this course: an agent is a base model placed in a closed loop with an environment — and almost everything that makes agents hard is ordinary systems engineering (state, reliability, cost, security, observability) showing up in an unusual regime. Your existing instincts transfer. The new skill is developing taste for what the model does well unaided versus where it needs scaffolding.

Who this is for

  • You’re a senior/staff-level engineer. You’ve built complex systems. You understand distributed systems, APIs, testing, deployment.
  • You’ve called an LLM API but haven’t built agentic systems.
  • You want depth, not a tutorial that stops at “here’s a chatbot.” You want to understand the real production failure modes and how people solve them.

What you’ll be able to do at the end

  1. Explain precisely how an agent differs from a base model, and reason about where capability comes from.
  2. Build an agent loop from scratch (no framework) — tools, the loop, context management, sub-agents.
  3. Choose and use a production framework (LangGraph, the lab Agent SDKs) deliberately, knowing what each buys you.
  4. Build an eval harness — the single most important and most-skipped skill — and use it to gate changes.
  5. Instrument agents with tracing/observability and debug multi-step failures.
  6. Engineer for reliability, cost, latency, and security (prompt injection, sandboxing, permissions).
  7. Deploy a long-running/durable agent and reason about state, recovery, and human-in-the-loop.

How to use this course

  • Go in order. Each module builds on the previous. Concepts introduced early (the loop, tokens, context) are load-bearing later.
  • Do the exercises. Reading about agents teaches you the vocabulary; building them teaches you the engineering. Every module ends with a hands-on exercise and a “Check yourself” section.
  • Build the running project. A single project — a coding/research agent you’ll call Scout — grows across the course. You build its loop in Module 3, give it memory and retrieval in 4–5, evals in 8, observability in 9, hardening in 10–11, and deploy it in 12. The capstone (Module 14) takes it to production-grade.
  • Read the primary sources. Each module links to the canonical engineering writing (Anthropic, OpenAI, framework docs, key papers). resources.md collects them. The field moves fast; learn to read the source.
  • Keep a lab notebook. Seriously. Keep a running notes.md of surprises, failures, and “huh” moments. Reading your own transcripts is how you build taste (see Module 8).

Conventions

  • Code is Python (the dominant language for agent engineering). TypeScript equivalents are noted where they matter.
  • The model API used in examples is Anthropic’s Claude (current models and SDK), but every concept is provider-agnostic — the loop, tools, context, evals, and deployment patterns are the same whether you use Claude, GPT, Gemini, or open models. Where something is provider-specific, it’s flagged.
  • 📖 marks a primary-source reading. 🛠️ marks a hands-on exercise. ✅ marks a self-check.

The modules (14 core + 4 deep-dives)

Part I — Foundations (Days 1–3)

  • Module 0B — The Python You Need for Scout — deep-dive / reference. The advanced Python that Scout’s source actually uses — dataclasses vs. Pydantic, closures and injected callables, context managers, async generators, threads/asyncio/subprocesses, contextvars, durability with fsync — each anchored to the file that uses it. Skim now, return when a construct bites.
  • Module 01 — The Base Model & the Completion API — LLMs as stateless functions, tokens, sampling/temperature, the messages API, prompting, structured output.
  • Module 1B — Prompting, Instructions & Steering — deep-dive. Prompts as code: the anatomy of a system prompt, steering behavior (verbosity, autonomy, tool-triggering), reasoning/effort, authority channels, prompt rot — and why you iterate against evals, not vibes.
  • Module 02 — Tool Use / Function Calling — the core primitive that turns a text model into an agent. Tool schemas, the request/response shape, designing a tool surface.
  • Module 03 — Build a Minimal Agent From Scratch — Project: Scout v0. The agent loop with no framework. Tools (read/write/bash), the loop, the permission gate. This is the heart of the course.

Part II — Core Engineering (Days 4–7)

  • Module 04 — Context Engineering & Memory — the context window as a managed resource. Truncation, compaction, the filesystem-as-memory pattern, sub-agents as context firewalls.
  • Module 05 — Retrieval & Knowledge (RAG → Agentic RAG) — embeddings, vector search, RAG vs. long context, agentic/iterative retrieval. Give Scout a knowledge base.
  • Module 06 — Multi-Agent Systems & Orchestration — workflows vs. agents, the canonical patterns (chaining, routing, parallelization, orchestrator-worker, evaluator-optimizer), and the lossy sub-agent interface.
  • Module 07 — The Framework Landscape — LangGraph, OpenAI Agents SDK, Claude Agent SDK, CrewAI, Google ADK. When to use what, and when to use nothing. Rebuild Scout in a framework.

Part III — Production (Days 8–12)

  • Module 08 — Evaluation & Testing — the most important module. Building an eval harness: datasets, graders (programmatic / LLM-as-judge), pass@k vs. pass^k, regression gating, the production→eval flywheel.
  • Module 09 — Observability, Tracing & Debugging — traces vs. logs, spans, Langfuse/LangSmith/Braintrust, debugging multi-step causal-chain failures.
  • Module 10 — Reliability, Cost & Performance — retries, fallbacks, structured-output validation, prompt caching economics, model tiering/routing, the quadratic-transcript problem, latency.
  • Module 10B — Model Customization: Fine-Tuning, RFT & When to Train — deep-dive. The prompt→context→tools→fine-tune ladder; what fine-tuning does (and doesn’t) do; SFT / DPO / RFT / distillation; and the honest “should you even train?” decision.
  • Module 11 — Security, Safety & Guardrails — prompt injection (the SQL injection of this stack), OWASP Top 10 for Agentic Apps, permission engines, sandboxing, human-in-the-loop, guardrails.
  • Module 11B — The Human Interface: Steering, Escalation & Trust — deep-dive. The product/UX layer as the trust mechanism: steering a running agent, escalation calibration, making long runs legible, plan mode, approval UX, and inspect/correct of live runs.
  • Module 12 — Deployment & Durable Execution — serving agents, state, durable execution (Temporal, LangGraph checkpointing), long-running/background agents, deploying Scout.

Part IV — Frontier & Capstone (Days 13–14+)

  • Module 13 — Frontier & Advanced Patterns — long-running/persistent agents, the “loop” discourse, RL-trained agents, computer use, MCP ecosystems, where the field is heading.
  • Module 14 — Capstone Project — take Scout (or a project of your choice) to production-grade: evals + tracing + guardrails + deployment, with a ship-readiness review.

Prerequisites

  • Comfortable in Python (3.10+). You don’t need ML experience.
  • An API key for at least one frontier model provider (setup in Module 0).
  • ~$20–50 of API credit will comfortably cover every exercise (most use small/cheap models; evals are the main spend).
  • Docker (for the sandboxing and deployment modules) — optional but recommended.

Suggested pace

This is designed for 1–2 weeks of focused full-time study, ~1 module per half-day with exercises. It compresses to a week if you skim the framework module and skip the capstone, or expands to a month part-time. The modules most worth slowing down on: 03 (the loop), 08 (evals), and 11 (security) — these are where the depth-of-understanding payoff is highest.

Start with Module 0 — Setup.
